# Changelog

## Unreleased
- **Sub-mesh visibility probe now mirrors wrapped duplicator generators and shared sub-meshes.** Duplicators using a wrapped generator (such as `sortDistribution` over `gridDistribution` on `generator.input`) had their config under `generator.input.*`, which `mirrorHost` skipped, leaving the probe as a default 3×3 grid and losing the visibility cull. `mirrorHost` now copies the generator types on `generator` and `generator.input` via `api.setGenerator` before copying all `generator.*` attributes and transforms. A single `subMesh` feeding multiple duplicators now measures and injects every host duplicator instead of only one, matching baked layers by name and tracking claimed layers so equal-count duplicators do not collide.
- **Cropping to the playback range no longer shifts the time base.** A playback range narrower than the comp was exported by setting the comp's `startFrame` to the playback start, so Cavalry's time base moved by 30 frames and every frame read landed 30 late. A colour cycle that begins teal exported its first key as the purple it reaches 30 frames in, so the Lottie started purple and looped from the wrong end. The crop now leaves the comp's `startFrame`/`endFrame` as authored and asks the render queue for a Custom Range instead (`frameRangeMode: 2`, `frameRange: {x: from, y: to}`), which still produces `ip`/`op` equal to the playback range. Frame reads inside the exporter are converted from the authored label to the read frame through the comp's `startFrame`, so a comp authored with a non-zero start still reads the right frames.
- **A shader image fill now exports as a real image.** Cavalry's Lottie writer drops an `imageShader` fill entirely: the shape bakes as a flat `fl` of its material colour and the document gets no image asset at all, so a comp full of mango cells exported as empty green squares. The exporter now captures the shader fill IN CONTEXT — hide everything the shader does not depend on, zero the shape's material alpha so only the shader's own pixels remain, render the comp at 1:1 on a transparent background, then restore — and crops one lattice cell out of that capture in plain JS (`png.js`; `sips` is unavailable — `api.runProcess` does not exist in every script context Cavalry runs a script in). The cell is repeated over every duplicator copy as a real `ty:2` image layer parented to a null that carries the baked layer's transform, so each copy keeps its own animated scale curve. The capture has to happen in context: the same asset on the same shape draws 2.8x larger in a throwaway comp than inside the real one, so a comp built to the cell size bakes the wrong size (measured: 250 px of a 314 cell against 91 px of a 142.5 cell). Discovery follows composition references, so a shader inside a referenced comp (the usual case — the card holds MangoGrid by reference) is found, and the capture hides the WHOLE tree it does not need rather than only the comp's direct children, because the card text sits under the same top-level group as the duplicators. Every layer the capture hides or changes is restored, and the cell PNG is copied into the export folder so `packImages` resolves it like any other image.
- **Driver nodes no longer leak into the export as empty layers.** Cavalry's writer emits an empty, shape-less layer for non-renderable comp children such as a falloff (`visibilityCurve`) that drive a sub-mesh attribute. They draw nothing, only pad the file, and the pivot/transform passes then call `api.getPivotPosition` on a node Cavalry cannot resolve, spamming `Couldn't find layer: <id>` on every export. Such layers are now dropped at the mapping stage, and `samplePivots` skips the same non-renderable driver types outright, so the console error is gone and the exported file no longer carries the dead layer.
- **Visibility gates export as real `h:1` hold keys, not eased steps.** A boolean `shapeVisibility` gate (a copy toggling once a seeded Random's animating seed crosses an integer) was written as keyframe tangents (`i:{x:[1],y:[1]}`, `o:{x:[0],y:[0]}`) with no hold flag, which players interpolate into a ramp instead of a discrete on/off. Gates are now emitted as canonical hard holds (`h:1`) that step exactly at the re-roll frames, so an Animated-visibility rig clicks between per-copy states rather than fading through them. Opacity fades are unaffected and stay a thinned linear curve.
- **Sub-mesh measurement cleanup can no longer delete the user's layers.** The clone-measurement probe's `cleanup` trusts the `compsBefore`/`layersBefore` snapshots captured when it was created, and a malformed state made those exclusion sets empty, deleting every layer not in them — including the user's own comps. `cleanup` now refuses to touch anything unless both snapshots are real arrays; a bad state logs a warning and deletes nothing.
- **Animated-seed per-copy drivers are now reproduced over time.** When a `Random`/`Noise` feeding `shapeVisibility` or `shapeOpacity` has an animating seed (a keyframed seed, or a driven seed), its per-copy value is no longer baked at a single frame: the seed re-rolls each copy every time it crosses an integer, so the per-copy value is piecewise-constant over the timeline. The exporter now reads the driver's seed once per frame to find the crossing instants, bakes the per-copy value just after each crossing, and writes the result as `tr.o` hold keys at exactly those frames — a handful of keys per copy instead of one per frame. Verified end-to-end on the Animated visibility comp (compNode#18): 36 copies, a seed 0→8 over frames 0–82 driving `random#37`, and a falloff-gated `value#79`; the export reproduces the AND of both gates at every frame, with 16 copies marked `hd` (hidden throughout) and 20 carrying animated hold keys that match the live per-frame gates exactly.
- **Sub-mesh visibility: driven `shapeVisibility` and driven `shapeOpacity` are now reproduced per copy.** Cavalry's writer drops both, so a culled copy exported as always-visible and an oscillator fade exported as a flat 100. The exporter now reads each duplicator deformer's driver from the scene graph and writes the result onto the matching baked shape groups as `tr.o`: a rig keeping a copy hidden at every frame is marked `hd` and stripped by the existing removeHidden pass, a copy that toggles gets hold keys, and a copy under a fade gets a thinned linear opacity curve. Drivers are reproduced when they are decidable: a Visibility Sequence connected to `shapeVisibility` (its documented window re-evaluated per frame), a JavaScript utility whose expression is index-pure (`ctx.index`/`ctx.count`, evaluated per index), and an Oscillator driving `shapeOpacity`. An oscillator is closed-form, so its per-frame value is computed rather than measured — the formula was fitted against live Cavalry reads for all four wave shapes and both trig types at 1 Hz / 60 fps, including the two Strength modes (`Strength Fades to Zero` scales the output; unchecked scales from `minimum`), Tan (refused: unbounded), and `timeMode 1` (BPM, frequency/60). The curve is a Ramer-Douglas-Peucker thinning in (frame, value) space with a 0.75/100 tolerance, so a plain sine costs a handful of keys instead of one per frame: sampling every frame on the 476-copy Quiz BG rig would have been ~430k keys (~27 MB), and per-copy sparse keys ~574 kB, versus a few keys for a shared curve. Deformers on one duplicator MULTIPLY (a gate zeroes a fade), matching how Cavalry combines them.
- **Removed the baked-geometry visibility readout.** It measured a debugging tap rather than the rig: with the tap removed, all 476 Quiz BG copies baked at one orientation, a visibility-connected and a visibility-disconnected bake differed in 0/476 groups, and the readout's probe mutated the scene (it swapped the duplicator's input shapes), which under `Random > Use Layer as Seed` re-rolled the very values it was reading. With the analytic drivers above it returned nothing on any real rig, so it was deleted along with `pathEdgeAngle`, `orientationClusters`, `maskForModes`, `angleAtTime`, `scanBakedGeometry`, `readSubMeshGeometryMasks`, `anchorVisibleMode`, `rawBakeJson`, `geometryTapPolarity`, `evalAngleExpression` and the `visible` side of `subMeshDriverMasks`.
- **Removed the falloff visibility evaluation path.** It walked every frame of every falloff to decide which cells a falloff hid, which was the dominant cost of a large export (three frame loops per export on the 476-copy Quiz BG rig), and it answered a question the per-copy driver readout already covers: a falloff feeding a `shapeVisibility` or `shapeOpacity` value IS a per-copy driver. `cullFalloffHidden`, `staticFalloffOf`, `falloffValueAt`, `refAnchor`, `asArrayK`, `graphSamplerFromSerialised` and their call site are gone; no falloff is evaluated in JS during export any more.
- **Computed visibility multiplies into an existing opacity curve instead of replacing it.** A baked copy whose `tr.o` is already animated (an authored layer fade, or a hand-edited export) now has the computed per-copy value multiplied into that curve frame by frame. A hidden copy still goes to zero; a visible copy keeps its authored fade. Previously such a group was skipped entirely, so an authored animation silently overrode the computed cull. A group whose computed value is not uniformly full but whose product with the authored curve is zero at every frame is marked `hd` and stripped. A copy that is fully visible throughout is still left untouched, so its authored curve survives byte-for-byte.
- **Seeded drivers are now measured inside Cavalry.** A Random, Noise or Value-with-falloffs feeding `shapeVisibility` or `shapeOpacity`, and an Oscillator on `shapeOpacity` whose `timeOffset` is driven per copy, have per-copy values only Cavalry can compute (`api.get` always evaluates at the default dynamic index, and `cavalry.random` does not reproduce a node's stream). Export now builds a throwaway probe comp holding a deep duplicate of the host duplicator, routes the driver through two math nodes into the duplicate's `shapeTimeOffset` (`value·0.004 + 0.5`), feeds it a rectangle whose width ramps 0→200 over the probe's two frames, and bakes it on the next script execution via `api.Timer`. Each baked copy's width at frame 0 is that copy's value (readable range ±125, resolution about 0.0025). The node measured is always the one connected to the sub-mesh attribute: measuring further upstream reads a different roll, because a Random's per-copy value depends on the layer it feeds. The probe is matched to the baked copies by position, and the probe comp and every layer it created are deleted afterwards.
- **Measured semantics.** `shapeVisibility` from a number is visible at ≥ 0.5. `shapeOpacity` is clamped to 0..100. An Oscillator's `timeOffset` is in SECONDS (the earlier formula added it in cycles, wrong for any frequency other than 1 Hz). A measured oscillator is read at two playhead frames a quarter cycle apart and each copy's phase solved from them, so its fade is written from the closed form at every frame; this covers the Normal (sine) wave, other wave shapes are left visible. Cavalry's Lottie writer negates y, so copy centres from the scene are flipped before pairing with baked groups; the old pairing mirrored rows for every index-pure driver.
- **Quiz BG result.** 476 copies: 368 gate-hidden copies are stripped and 108 visible copies carry a per-copy oscillator fade, 895 opacity keys in total (about 8 per copy). The optimised file is 388 kB, down from 1.05 MB, and its predicted per-copy opacity correlates 0.94–0.996 with Cavalry renders at frames 60, 300 and 500 with no hidden copy drawn. Rigs marked `Use Layer as Seed` are still left visible (rewiring may re-roll them) and remain the planned follow-up.
- **Build ID is now a 6-character alphanumeric code** derived from the build timestamp (e.g. `CX3DBU`) instead of the raw epoch milliseconds, shown beside the version in the settings menu. `node dev/verify-build.cjs <code>` recomputes the expected code from the recorded build time and checks it is present in the built bundle, so a running script can be matched to the build it came from.

## Lottie Optimiser 1.3.0 (unreleased additions)

- **shareSameShape now reuses the exporter's own precomp assets.** Groups whose geometry, colour curve and hold-blink pattern match an existing asset demote onto it instead of duplicating their full curves in the main layer (master copies included). Hold-blink matching tolerates the final key's omitted `h` flag.
- **binaryWindows profitability guard.** A paint-driven blink split no longer fires when the blinking paint is a minor part of a large layer (a 1.5KB blink beside an 8.5KB colour curve made each window clone more expensive than the dead frames saved).
- **decomposeSharedPaints (new pass).** The exporter writes one precomp per (colour curve, blink phase) combination, so copies sharing an expensive animated colour curve but blinking on different phases each store their own curve. The pass groups single-fill shape assets by byte-identical colour curve, retargets every family member's refs to one representative (its blink forced to static full) and moves each blink onto the ref layer's own opacity, which Lottie multiplies with the asset's paint. Profitability guard skips families where added ref blink bytes exceed the dropped layers.
- **cullFalloffHidden also follows shapeOpacity chains** (not just shapeVisibility) and accepts base values of 1 and 100, so falloff-driven `shapeOpacity` rigs cull hidden cells too.
- **stripZeroOpacity (new pass).** Removes anything that is 0% opacity at every frame: layers with an all-zero opacity (static or animated), fill paints with an all-zero opacity, and groups whose own opacity is all-zero. Complements the static-only layer removal; sub-mesh falloff rigs that bake some copies to zero now lose them entirely.
- **cullFalloffHidden now culls ref layers too.** Precomp ref layers (the demoted duplicator copies) are tested against the decoded static falloff at their on-screen position and dropped when they land at exact zero — previously only in-layer groups were culled, so stacked duplicators kept their hole cells.
- **binaryWindows layer-opacity split profitability guard.** A layer-driven blink split that would deep-copy the layer more often than the dropped blink curve saves is skipped.
- Grid duplicator exports: 1.4MB → 524KB on the reference scene, pixel-perfect (0.000% worst-frame difference over 24 frames).
- **restructureSharedAnim (new pass).** The existing duplicator restructure shares only geometry and keeps every per-copy keyframe, so it saved 4.3% here. This pass shares the *animation*. A duplicator's copies are one animation sampled at a per-copy time offset, so the copies collapse to one precomp asset carrying the shared curves plus one `ty:0` reference per copy whose `st` carries that copy's delay. Delays are **measured by fitting** each copy's baked channel against a reference copy, not decoded from the scene's driver graph, so Stagger, Random, Noise and keyed drivers all work and no extra Export click is needed. Position keys are kept verbatim (they carry the Stagger-delayed x movement exactly); only the scale channel moves onto the asset. On the reference scene: 91 copies, one 184×184 rounded square, delay span 14.9 frames matching `random#3`'s 0…−15, fit residual 0.0009 of the channel's range, **45.2% smaller** with a worst-frame render difference of 0.394% and 0.000% from frame 55 on. The accept/reject line is the fit residual, calibrated at 0.005: a copy under a genuinely different ease scores 0.018 and a two-step ramp scores 0.040, so a duplicator that misses the gate is left to the geometry-only pass rather than half-rewritten. Rotation is dropped because the exporter synthesises it from shear during the bake and it is an exact multiple of 90° at full scale on a shape invariant under 90° rotation. It runs as a pipeline pass immediately after **Turn baked moving shapes back into transforms**: Cavalry bakes a duplicator's motion into per-frame paths with static transforms, so this pass can only see the shared animation once that recovery has turned them back into animated transforms. On a realistic trimmed bake of the grid scene the pipeline goes 878 KB → 510 KB (**41.9%**) with a worst sampled frame of 0.396%.
- **The replaced layer's transform rides a parent null.** The layer's own transform is carried on a ty:3 null rather than folded onto the refs. A baked duplicator holds the comp-level scale on the layer (1139% → 100% here), so dropping it drew the whole grid at full size for the animation — a 67.8% pixel error with an otherwise excellent fit residual. A second null carries the container group's transform, and the outer one keeps the layer's original parent.
- Non-duplicator shape groups on the same layer now survive the rewrite as their own shape layers. They were being dropped, which lost pixels at the frames before the copies reached full scale. Precomp ref layers also carry `w`/`h`, without which lottie-web's clip rectangle is undefined and every reference renders empty. New layers are numbered above every `ind` already in the document, so a duplicator sitting beside other layers cannot reparent them.
